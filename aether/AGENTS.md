# AGENTS.md — 《에테르 Z+》 프로토타입

이 프로젝트에서 작업하는 AI 에이전트를 위한 지침. 엔진 자체를 고치려는 게 아니라면
`engine/docs/ai-workflow.md` 와 `engine/docs/3d.md` 를 먼저 읽는다.

## 이 프로젝트가 무엇인가

Unity 본편을 만들기 전에 **재미를 검증하는 장치**다. 완성도보다 다음이 우선이다.

1. 각 챔버는 기획서 33장의 검증 항목(T1~T5) 중 하나를 정면으로 겨냥한다.
2. "이 능력 조합으로만 풀린다"는 설계 의도는 반드시 `test/chambers.test.js` 로 못 박는다.
3. 밸런스 숫자는 추측하지 말고 **헤드리스로 재서** 정한다.

## 작업 루프

```sh
node engine/src/cli/sjl.js validate      # 씬을 고쳤으면 매번
node engine/src/cli/sjl.js doctor
node --test test/*.test.js               # 설계 의도가 살아 있는지
```

세 개가 다 통과하지 않으면 끝난 게 아니다.

## 규칙

**레벨은 씬 파일에 둔다.** `scenes/*.json` 이 레벨의 전부다. 위치·크기·임계값을 코드로 계산하지 않는다.

**능력은 `src/law.js` 한 곳에서만 바뀐다.** 새 능력을 추가할 때 손대는 곳은 `SERIES` 표와
`castLaw` 의 분기 하나뿐이어야 한다. HUD·계측·입력은 전부 그 표를 읽는다.

**임계값을 바꾸면 먼저 잰다.** 예: 초강화벽을 조정한다면 "무게만 / 관성만 / 둘 다" 세 경우의
충격량을 헤드리스로 출력해 보고, 그 사이에 값을 놓는다. 감으로 정한 숫자는 챔버를 조용히 망가뜨린다.

**`Math.random()` 대신 `world.random`.** 결정론이 깨지면 헤드리스 테스트가 의미를 잃는다.

**씬을 다시 로드해도 world 는 같은 객체다.** `world.events.on(...)` 으로 구독했다면 `onDestroy` 에서
반드시 해제한다. 안 하면 챔버를 옮길 때마다 피해가 두 배, 세 배로 들어간다.

**법칙이 걸린 몸은 재우지 않는다.** 잠든 바디는 솔버가 통째로 건너뛰므로, 떠오르는 발판이
밀어 올려도 반응하지 않는다. `LawWorld` 가 `canSleep` 을 꺼 주고 있다 — 되돌리지 말 것.

## 하지 말 것

- 챔버에 정답을 알려주는 UI를 붙이는 것. 힌트는 H 키로 **플레이어가 요청할 때만** 나온다.
- 능력을 선택하는 메뉴/휠을 만드는 것. 기획서의 핵심은 "메뉴 없이 손에 익는 조작"이다.
- 검증과 무관한 콘텐츠를 늘리는 것. 챔버 하나가 검증 항목 하나를 감당하지 못하면 잘라낸다.
