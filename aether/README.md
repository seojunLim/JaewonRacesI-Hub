# 《에테르 Z+ : 세계의 법칙》 — 3D 프로토타입 검증판

Unity로 본편을 만들기 전에 **"이 설계가 정말 재미있는가"** 만 확인하기 위한 플레이어블 프로토타입.
기획서 33장 「프로토타입에서 반드시 검증할 것」의 5개 항목을 챔버 단위로 나눠 직접 만져 볼 수 있게 했다.

- 엔진 : [SJL Engine](https://github.com/seojunLim/SJL-GAME-ENGINE) (의존성 0, 빌드 단계 없음, 결정론적)
- 플레이 : `aether/index.html` — WebGL2를 지원하는 데스크톱 브라우저
- 조작 : WASD 이동 · Space 점프 · Shift 회피 · 좌클릭 공격 · 방향키/휠 카메라
  **Z(누르고) → Q/E/R 계열 선택 → 좌클릭·우클릭·E·Shift 발동**

---

## 검증 항목과 챔버

| 챔버 | 겨냥하는 검증 | 통과 조건으로 삼은 것 |
|---|---|---|
| 1 깨어남 | T5 타격감 | 능력 한 번으로 세계가 눈에 띄게 바뀌는가 |
| 2 무게의 방 | T1 무게 단독 · T4 실험 | 한 장벽을 **세 가지 방법**으로 넘을 수 있는가 |
| 3 구르는 것들 | T2 관성 단독 | 관성만 쓸 수 있는 방에서 벽을 넘길 수 있는가 |
| 4 두 법칙 | T3 조합 | 무게만·관성만으로는 **실패**하고 겹쳐야 성공하는가 |
| 5 사라지는 것들 | T3 · T4 | 들어갈 수 없는 방의 스위치를 누를 수 있는가 |
| 6 반응하는 것들 | T4 | 적을 "죽이는" 것 말고 "반응시키는" 해법이 나오는가 |
| 7 낙하를 잊은 자 | T3 · T5 | 보스가 법칙 조작을 요구하는가 |
| 8 자유 실험장 | 전 항목 | 목표 없이 10분을 놀 수 있는가 |

플레이가 끝나면 **검증 리포트**(자동 계측 + 1~5 자기 평가)가 나오고, 마크다운으로 복사할 수 있다.
계열별 사용 비율이 크게 치우치면 그 능력은 아직 "쓸 이유"가 부족하다는 신호다.

## 설계에서 정한 숫자

능력의 세기는 전부 **충격량 = 질량 × 충돌 직전 속도(kg·m/s)** 하나로 환산된다.
플레이어가 이해해야 하는 수치가 하나뿐이라 실험이 쉬워진다.

| 벽 | 임계값 | 통과하는 방법 |
|---|---|---|
| 균열 바닥 | 300 | 무거워진 물체 낙하 / 자기 무게 슬램 |
| 강화벽 | 1,200 | 사출된 바위(700)로는 부족 → **관성 증폭**(1,600) |
| 초강화벽 | 7,000 | 무게만(5,300)·관성만(1,600) 실패 → **무게+증폭**(12,500) |

`무게 증가` ×8 · `무게 감소` ×0.25 + 상승 2.2m/s · `관성 증폭` ×2.2 · `방향 변경` 최소 13m/s.
숫자는 전부 `src/law.js` 상단 상수에 모여 있다.

## 개발

```sh
cd aether
node engine/src/cli/sjl.js validate     # 씬 검사 (오타·잘못된 필드·끊긴 참조)
node engine/src/cli/sjl.js doctor       # 카메라 없음, 콜라이더 없는 리지드바디 등
node engine/src/cli/sjl.js run --scene scenes/c3-inertia.json --frames 300 --ascii
node --test test/*.test.js              # 챔버 16개 시나리오
node engine/src/cli/sjl.js dev          # 라이브 리로드 개발 서버
```

`node --test`는 "무게만으로는 초강화벽이 안 부서지고, 무게+관성이면 부서진다" 같은
**설계 의도 자체**를 검사한다. 밸런스를 건드리면 여기서 먼저 깨진다.

## Unity로 옮길 때 살릴 것

프로토타입에서 실제로 재미가 나온 지점만 적는다.

1. **부양은 물리가 아니라 법칙이다.** 가벼워진 물체는 위에 사람이 올라타 있어도 일정 속도로
   떠오른다(솔버에 지지 않도록 키네마틱으로 전환). "물리적으로 맞는" 구현은 재미가 없었다.
2. **위상화는 중력까지 지운다.** 충돌체만 끄면 물체가 바닥으로 가라앉아 버린다.
   중력을 끄고 감쇠를 주면 "밀어 넣은 만큼 미끄러지다 그 자리에서 실체화"가 되어 조작이 읽힌다.
3. **증폭은 움직이는 것에만.** 멈춘 물체에 실패를 돌려주는 대신 `방향 변경`이 최소 속도를 주게 해서,
   "먼저 움직이게 만든다 → 증폭한다"는 2단 사고가 자연스럽게 생겼다.
4. **파괴 임계값을 숫자로 보여준다.** 모자랐을 때 `700 / 1200` 을 띄우면 다음 시도가 실험이 된다.
5. **적에게는 충격량이 근접 공격보다 10배 아프다.** 이 비율이 "얘는 무엇에 반응하지?"를 만든다.

## 발견한 엔진 버그 (SJL Engine)

`engine/src/systems/behavior.js` 의 `deliver()` 가 충돌 노멀을 뒤집을 때 **z 성분을 잃는다.**

```js
const normal = payload.normal
  ? flipNormal
    ? { x: -payload.normal.x, y: -payload.normal.y }   // ← z 누락
    : payload.normal
  : undefined;
```

2D 전용 코드가 3D 디스패치에도 쓰이면서, 충돌쌍의 `b` 쪽 엔티티의 `onCollisionEnter` 는
`{x, y}` 만 받는다. 이 노멀로 내적을 하면 `NaN` 이 되고, 이 프로토타입에서는
"플레이어가 내리찍었는데 균열 바닥이 안 부서진다"로 나타났다.

고치려면 `{ x: -n.x, y: -n.y, z: -n.z }` 로 z 를 포함하면 된다.
이 저장소의 `engine/` 사본은 업스트림 그대로 두었고, 게임 쪽(`src/law.js` 의 `impactOf`)에서
z 가 없는 노멀이 오면 접근 속도의 크기를 쓰도록 방어했다.

## 알려진 한계

- 3D 솔버는 회전을 시뮬레이션하지 않는다(엔진의 의도된 트레이드오프). 그래서 경사면을 굴리는 대신
  **사출기**로 운동을 만들어 준다. Unity에서는 실제 회전이 있으므로 기획서대로 경사면을 써도 된다.
- 콜라이더가 축 정렬이라 기울어진 지형이 없다. 램프가 필요하면 계단으로 쌓아야 한다.
- 사운드는 넣지 않았다. 타격감(T5) 평가는 화면 효과와 시간 감속만으로 판단해야 한다.
